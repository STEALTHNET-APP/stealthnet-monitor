# Панель мониторинга: структура экранов и взаимодействий

Статус: предложение интерфейса для обсуждения. Макеты и приложение пока не реализованы. Масштаб и назначение главной страницы подтверждены; конкретная композиция, визуальная система и дополнительные функции ниже предложены.

## 1. Задача интерфейса

Режим Operate: владелец управляет вниманием, следит за сетью и расследует отклонения. Масштаб — сотни нод, десятки тысяч пользователей. Первая страница отвечает: что происходит во всей сети, где нагрузка и какие проблемы требуют внимания.

Основной путь: общий показатель → группа или нода → выбранный интервал → подключение или событие → подтверждённые подробности.

Критерий успеха: переход между этими уровнями сохраняет время, фильтры и контекст. Пользователь видит источник, единицу измерения и свежесть каждого показателя.

## 2. Навигация

Постоянное левое меню с четырьмя группами. Названия видны рядом с иконками. Числовой бейдж означает необработанные проблемы, а его значение объясняется подсказкой.

| Группа | Раздел | Внутренние вкладки | Основная задача |
|---|---|---|---|
| Сеть | Обзор | Сводка · Сравнение групп | Понять состояние проекта |
| Сеть | Карта | География · Ноды | Найти проблемный регион или ноду |
| Инфраструктура | Серверы и ноды | Ноды · Серверы · Группы | Найти объект и открыть подробности |
| Инфраструктура | Мониторинг | Ресурсы · Сеть · Доступность | Сопоставить технические показатели |
| Инфраструктура | Трафик | Динамика · По нодам · По пользователям | Найти потребление и изменения |
| Пользователи | Пользователи | Все пользователи · Выбранный пользователь | Найти учётную запись и её историю |
| Пользователи | Подключения | Текущие · История | Исследовать наблюдаемые соединения |
| Пользователи | Устройства | Зарегистрированные · Связи с подключениями | Показать доступные сведения и качество сопоставления |
| События | Инциденты | Активные · История | Разобраться с отказами и деградацией |
| События | Торренты и жалобы | Обнаружения · Внешние жалобы | Исследовать активность и обращения |
| Управление | Оповещения | Правила · Каналы · История доставки | Настроить уведомления |
| Управление | Настройки | Интеграции · Агенты · Хранение · Доступ | Настроить систему |

«Выбранный пользователь» открывается как отдельная страница подробностей, а не постоянная вкладка без объекта. Управление располагается отдельным нижним блоком меню. Поиск доступен из верхней панели и с клавиатуры.

Верхняя панель: текущий раздел, глобальный поиск, выбранный период и часовой пояс, свежесть данных, «Добавить сервер». Глобальные фильтры: группа, регион и нода. Применённые фильтры всегда видны.

## 3. Обзор — первая страница

### Первый экран

1. Заголовок «Обзор сети», текущий период и отметка последнего обновления.
2. Компактная строка показателей: доступные ноды / всего, пользователи онлайн, текущая скорость, трафик за период, активные инциденты.
3. Главная область: широкий график входящей и исходящей скорости; под ним выровненный по времени график пользователей онлайн.
4. Правая колонка: сводка проблем, затем наиболее загруженные ноды. Строки открывают расследование с тем же периодом.
5. Ниже: компактная карта регионов и таблица нод, отсортированная по выбранному показателю.

Внутри длинных таблиц — управление колонками, сортировка, поиск, сохранённые представления. На первом экране показывается ограниченная выборка с явным переходом ко всем объектам.

### Смысл показателей

- «Пользователи онлайн» — уникальные учётные записи по определённому окну активности; окно видно в подсказке.
- «Соединения» — отдельный показатель, не подменяющий число людей или устройств.
- Скорость имеет единицу бит/с; объём — байты с подходящим префиксом.
- Свежесть и доступность агента, Remnawave Node и внешней проверки различимы.
- Сумма по узлам используется только там, где нет двойного учёта; метод агрегации объясняется.

## 4. Карта

На уровне всей сети видны группы по регионам и ноды. По мере приближения раскрывается детализация. Панель справа показывает выбранную ноду, показатели и список связанных регионов.

- Режимы окрашивания: состояние, скорость, число подключений.
- При наведении на ноду: название, регион, доступность, скорость, пользователи, свежесть данных.
- При выборе ноды: только связанные с ней направления и соответствующие фильтры списка.
- Толщина линии означает конкретный выбранный показатель; легенда объясняет масштаб.
- География входящих IP показана как приблизительная область. Неизвестное местоположение учитывается отдельной группой.
- Для источников за промежуточным прокси или CDN показываем наблюдаемую точку входа и качество сведений об исходном IP.
- Предусмотрен равнозначный список регионов и нод для клавиатуры, мобильного экрана и случаев недоступности карты.

## 5. Серверы и ноды

Табличный вид по умолчанию для большого парка; карточки — дополнительное представление небольших групп.

Основные колонки: название, регион, состояние ноды, состояние агента, CPU, RAM, скорость, пользователи, последний контакт. Пороговые значения сопровождаются текстовым состоянием.

Боковая область быстрого просмотра позволяет изучить строку, сохранив место в таблице. «Открыть ноду» ведёт на полноценную страницу.

### Вкладки страницы ноды

| Вкладка | Содержание |
|---|---|
| Обзор | Паспорт, раздельные состояния, ключевые графики, связанные инциденты |
| Ресурсы | CPU, RAM, диск, I/O, процессы и контейнеры при наличии данных |
| Сеть | Интерфейсы, скорость, ошибки, потери и задержка с указанием точки измерения |
| Трафик | Объём за период, направления, доступные разрезы, лидеры потребления |
| Подключения | Текущие и исторические наблюдения, поиск пользователя/IP |
| События | Ошибки, изменения состояния, обнаружения и связанные жалобы |
| Журналы | Доступные потоки журналов, фильтры и переход к выбранному времени |
| Агент | Версия, последняя связь, очередь данных, диагностика сбора |

Недоступная для данного агента возможность получает объяснение и способ включения. Настройки, которые могут менять работу ноды, отделяются от просмотра состояния.

## 6. Графики и hover

Единый контракт для всех временных графиков:

1. Hover показывает вертикальный курсор и компактную подсказку: точное время, часовой пояс, значения всех видимых рядов и единицы.
2. На соседних графиках одного расследования курсор синхронизирован по времени.
3. Клик закрепляет подсказку; Escape снимает закрепление. На телефоне используется касание.
4. Выделение диапазона приближает выбранный период; есть явная кнопка сброса и ввод дат без перетаскивания.
5. Легенда управляет видимыми рядами. Цвет каждого показателя постоянен между страницами; дополнительно применяются подписи и разные типы линий.
6. Маркеры инцидентов на временной оси открывают подробности события.
7. Действие «Открыть подключения за этот период» переносит интервал и фильтры.
8. Режим сравнения показывает предыдущий равный период с понятной легендой.
9. Пауза обновления позволяет читать график без сдвига шкалы; переход в live явный.
10. Разрывы сбора отображаются разрывами, нулевые значения — нулями. Для агрегированных данных в подсказке указаны интервал и функция: среднее, максимум или сумма.
11. Клавиатура позволяет перемещаться по точкам; доступна табличная сводка значений. Важная информация не существует только внутри hover.
12. Опциональная выгрузка относится к текущему отфильтрованному набору и показывает его границы.

Типы визуализаций выбираются по задаче: линии для динамики, столбцы для сравнения нод, накопленные области для ограниченного числа составляющих трафика, тепловая карта для регионов/времени. Десятки рядов заменяются лидерами и группой «Остальные» с раскрытием.

## 7. Пользователи, подключения и устройства

Карточка пользователя объединяет: профиль учётной записи, динамику трафика, наблюдаемые ноды/IP, устройства из поддерживаемых источников и связанные события.

Карточка подключения показывает доступные время/интервал наблюдения, ноду, пользователя, наблюдаемый IP, транспорт и источник данных. Точная длительность и признак завершения используются только при наличии соответствующих событий.

Устройства: ОС, тип, модель и клиентское приложение отображаются при наличии сведений. Отдельные подписи «сообщено приложением», «предположено» и «нет данных» показывают качество информации. Зарегистрированное устройство не объявляется подключённым без доказанного сопоставления. IP не используется как уникальный идентификатор устройства.

## 8. Инциденты, торрент-обнаружения и жалобы

Инциденты объединяют связанные сигналы в историю проблемы: начало, затронутые объекты, изменения и восстановление. Фильтры — важность, регион, нода и состояние обработки.

В «Торренты и жалобы» две самостоятельные вкладки:

- Обнаружения: время, нода, связанный пользователь при наличии, способ обнаружения, наблюдаемые признаки и доступные доказательства.
- Внешние жалобы: исходный текст/вложения, отправитель, время и адреса события, состояние разбора, результаты сопоставления и заметки.

Сопоставление жалобы раскрывает использованные поля, часовой пояс и качество результата. Варианты «данных достаточно», «несколько кандидатов» и «данных недостаточно» не смешиваются. Дизайн действий по блокировке и автоматизации остаётся открытым вопросом.

## 9. Добавление сервера

Отдельный пошаговый экран с возможностью вернуться к списку и продолжить подключение:

1. Сценарий: работающая нода / чистый сервер.
2. Параметры: название, группа; для новой ноды — нужные параметры Remnawave и профиль. Точный обязательный набор определяется интеграцией.
3. Команда: копирование, описание действия, срок токена, перевыпуск токена.
4. Прогресс: ожидаем запуск → установка → регистрация → проверка → готово. Состояния приходят из фактического установщика.
5. Результат: карточка сервера и ссылки на связанные ноды.

Состояния ошибок: истёк токен, сервер уже добавлен, нет связи с панелью, неподдерживаемая среда, частичное завершение. Повторный запуск должен быть предусмотрен в контракте установщика. Пароли и секреты скрыты в истории событий и диагностике.

## 10. Современная визуальная система — требования к следующему этапу

Палитра, шрифты и конкретная композиция пока не утверждены. Следующий визуальный макет должен продемонстрировать:

- Иерархию: общая сеть → группа → нода → событие, с ясным расположением на каждом уровне.
- Выразительные, читаемые графики и аккуратную числовую типографику; значение не сдвигает соседние элементы при обновлении.
- Плотные, хорошо выровненные таблицы с управляемыми колонками.
- Единые состояния наведения, выбора, фокуса, загрузки и ошибок.
- Согласованные обозначения состояния и рядов данных на всех экранах.
- Короткие переходы, которые показывают результат действия, с поддержкой уменьшенного движения.
- Светлую и тёмную темы как предложение, требующее проверки графиков и контраста в обеих.
- Состояние системы, понятное по тексту и иконкам в дополнение к цвету.

Фокус первого визуального макета: обзор сети, страница ноды, закреплённая подсказка графика и выбор режима добавления сервера. Остальные вкладки наследуют выбранную систему.

## 11. Масштаб, адаптация и состояния

- Серверная фильтрация и пагинация либо виртуализация длинных списков; точный вариант определяется реализацией.
- Поиск и группировка до загрузки большого набора объектов.
- Разная агрегация временных рядов для коротких и длинных периодов с сохранением важных максимумов.
- Кластеризация карты и детализация по выбору объекта.
- Интервал обновления и свежесть видны; целевые задержки уточняются после измерений.
- Общая потеря связи и устаревшие данные заметны на всех экранах.
- Пустая система ведёт к добавлению сервера; пустой результат поиска предлагает изменить фильтры.
- Загрузка сохраняет структуру страницы; ошибки отдельных виджетов не скрывают остальные данные.
- На узком экране: выдвижное меню, графики в одну колонку, приоритетные поля списка и разворачиваемые строки, подробности на отдельном экране.
- Основные сценарии доступны клавиатурой; карта имеет список-альтернативу; текст масштабируется без потери действий.

## 12. Матрица демонстрационных сценариев

Для будущего прототипа использовать явно подписанные синтетические данные:

| Сценарий | Что должен доказать макет |
|---|---|
| Нормальная работа большого парка | Читаемая сводка и быстрый поиск ноды |
| Рост задержки в группе | Переход от сводки к графику и событию |
| Агент потерял связь | Отличимость устаревших данных от нулей и от отказа ноды |
| Расследование пика трафика | Выделение времени и сохранение фильтров при переходе |
| Неизвестное устройство/география | Честное отсутствие сведений без выдуманных значений |
| Жалоба с неоднозначным сопоставлением | Понятные основания и несколько кандидатов |
| Установка прервалась | Видимый этап, объяснение и продолжение |

## 13. Что ещё предстоит выбрать

Визуальное направление и название; конкретный стек; точность и источники отдельных полей; роли; поддерживаемые платформы агентов; частота обновления; сроки хранения. Эти решения не считаются согласованными настоящим предложением.
